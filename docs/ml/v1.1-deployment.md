## Strict Keras–ONNX parity

Run `.\ml\deployment\onnx\.venv\Scripts\python.exe ml\deployment\onnx\migrate_v1_1.py` from the repository root. The detailed report is `ml/deployment/onnx/artifacts/v1.1/parity_report.json`.

- 20 inputs: four deterministic v1.0 reference tensors, 15 authoritative-notebook preprocessing goldens, and one real KA browser capture. The goldens exercise stroke lengths, multiple strokes, kudlit placement, aspect ratios, transparency, duration edge cases, and 512-point allocation. Only the KA capture carries a true label; the synthetic/golden tensors are conversion probes, not accuracy measurements for named classes.
- Top-1 agreement: **20/20**. Global maximum absolute difference across all 63 probabilities and all cases: **3.15904617e-6**, below the strict `<1e-4` gate. All outputs were finite and summed near one.
- On the real KA capture, v1.0 ONNX returned KE/KI at 75.31%; v1.1 Keras returned KA at 59.95% and v1.1 ONNX returned KA at 59.95%. This is one real example, not an estimate of class-level accuracy.
- The export script returns failure on any parity, shape, normalization-provenance, finite-output, or probability-sum violation. The app reference was changed only after this gate passed.

## App integration and rollback

The only production model selector is `BAYA_RECOGNITION_MODEL_VERSION` in `apps/mobile/ml/bayaModelConfig.ts`. It derives `/models/baya/Baybayin_EfficientNetB0_BiLSTM_1.1.onnx` for the browser service and records `modelVersion` in new diagnostic captures. The browser service lazily creates one WASM session, shares in-flight initialization, validates the four inputs and one output, and returns 63 probabilities. `writingRecognition.ts`, `efficientNetPreprocessing.ts`, `efficientNetClassLabels.ts`, the canvas, lesson target handling, confidence thresholds, and learner feedback were not changed for this migration. The learner view shows the primary result; optional top-N predictions remain confined to the diagnostic capture path.

To roll back, change that **one `BAYA_RECOGNITION_MODEL_VERSION` line** from `'1.1'` to `'1.0'`, then rebuild/reload the web app. Update the URL assertions in `apps/mobile/ml/__tests__/bayaModel.test.ts` when committing a rollback. The v1.0 public artifact and its normalization contract already remain in place. The Python capture diagnostic reads the recorded version; the earlier unversioned KA capture defaults to v1.0.

The preprocessing contract is documented in `apps/mobile/ml/README.md` and audited against `ml/training/EfficientNet_B0–BiLSTM.ipynb`. No preprocessing or class-index changes were made. The captured KA input matched the notebook's Python image and sequence preprocessing exactly before migration.

## Focused learner regression checklist

The following manual drawing checks are prepared; only the captured KA inference has been exercised with v1.1 in this migration. For each row, draw the intended symbol in the Module 3 writing screen and record the model's top-1 and confidence. Include different writers, stroke orders, and kudlit placement where possible.

| Family | Cases | Status |
| --- | --- | --- |
| GA | GA, GE/GI, GO/GU | manual browser drawings pending |
| KA | KA, KE/KI, KO/KU | captured KA tensor passed Keras/ONNX; manual browser redraw pending |
| DA/RA | DA/RA, DE/DI, DO/DU | manual browser drawings pending |
| Breadth | independent vowels, other base consonants, A forms, E/I forms, O/U forms | manual browser drawings pending |

For each attempt also check that only black learner ink reaches the raster input, the gray tracing guide is excluded, dimensions and timestamps are preserved, `stroke_start` is 1 only at the beginning of each stroke, and prediction follows the model's highest output probability rather than the lesson target. The existing capture JSON and Python diagnostic command in `ml/diagnostics/captures/README.md` can record and verify these points. Do not add target-aware overrides.

## Limits

The real-handwriting test dataset used for the supplied 97.35% result is unavailable locally. The parity suite contains one real labeled browser capture, so this migration establishes conversion fidelity and a corrected result for that capture, not independent remeasurement of aggregate model accuracy. Manual regression for the other named families remains pending.
